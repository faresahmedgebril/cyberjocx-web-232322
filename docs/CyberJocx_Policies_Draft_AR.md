# CyberJocx — مسودة السياسات والجاهزية القانونية قبل الإطلاق
**الإصدار:** 25 أكتوبر 2026  
**الحالة:** مسودة تشغيلية للمراجعة، وليست رأيًا قانونيًا أو سياسة منشورة نافذة. يجب اعتمادها مع محامٍ/محاسب مصري قبل جمع المدفوعات أو البيانات الشخصية على نطاق عام.

## 1. الخصوصية وحماية البيانات
يجب أن توضح النسخة المنشورة، على الأقل:
- الجهة المسؤولة عن معالجة البيانات ووسيلة التواصل معها والكيان القانوني المسجل إن وجد.
- فئات البيانات: حساب وبيانات اتصال، سجل تعلم وتقدم، محتوى المشاريع واللابات، تذاكر الدعم، بيانات الدفع التي تعالجها بوابة الدفع، سجلات الأمان، وسجلات استخدام AI.
- الأغراض والأساس القانوني لكل معالجة، وبيانات الحد الأدنى اللازمة، ومدة الاحتفاظ، والإجراءات الخاصة بالحذف أو إخفاء الهوية.
- الجهات التي قد تتلقى البيانات: مزودو الاستضافة، البريد، التحليلات، الدفع، ونماذج الذكاء الاصطناعي. لا ترسل كلمات المرور أو الأسرار أو بيانات حساسة أو ملفات عملاء إلى AI. يجب مراجعة شروط كل مزود، ومكان المعالجة، وإعدادات الاحتفاظ قبل التفعيل.
- آلية طلب الوصول أو التصحيح أو الحذف حيث ينطبق القانون، والتعامل مع الشكاوى، والاستجابة لحوادث البيانات، وسجل الوصول الداخلي.
- موافقات منفصلة لأي نشر لقصة متعلم أو صورة أو شهادة أو اقتباس يمكن أن يحدد شخصًا.

## 2. شروط الاستخدام والسلوك المقبول
- استخدام مختبرات CyberJocx فقط ضمن النطاق والأنظمة المصرح بها. يحظر استخدام المنصة لتجربة استغلال ضد أنظمة حقيقية دون إذن مكتوب.
- يحظر استهداف مستخدمين آخرين، أو سرقة بيانات اعتماد، أو رفع برمجيات خبيثة، أو نشر بيانات شخصية، أو تجاوز حدود الوصول أو الاستهلاك.
- لا يضمن CyberJocx وظيفة أو تدريبًا أو مقابلة. يمكن أن تكون هناك فرص محتملة للتقديم أو الترشيح بحسب التوافر، ومعايير الجهة المستضيفة وقرارها.
- يوضح كل عرض مدفوع ما يشمله السعر، ومدة الوصول، وحدود اللابات وAI، وسياسة الدعم، وأي خصائص تجريبية.
- يجب تحديد حقوق الملكية في محتوى المدرّبين، ومشروعات المتعلمين، وتراخيص اللابات، واستخدام المحتوى في الترويج.
- يجب نشر شروط الدفع والتجديد والإلغاء والاسترداد، وحدود المسؤولية بقدر ما يسمح به القانون، وآلية الشكاوى.

## 3. سياسة الإلغاء والاسترداد — بنود يجب اعتمادها
قبل أول عملية تحصيل، يجب اتخاذ قرار مكتوب بشأن:
1. هل التجديد تلقائي أم يدوي، وكيف يوقف المستخدم التجديد.
2. متى يتوقف الوصول عند الإلغاء، وكيف يُحسب الجزء المتبقي من الفترة.
3. حالات الاسترداد والاستثناءات، وموعد إعادة المبلغ، ورسوم الدفع غير القابلة للاسترداد إن كانت قانونية ومعلنة.
4. ما الذي يحدث عند تعطل المنصة أو إلغاء فعالية أو تغيير موعد برنامج خاص.
5. كيفية التعامل مع طلبات الاسترداد المتنازع عليها وحالات الإساءة/الاحتيال.
لا تُنشر سياسة تمنع حقًا إلزاميًا مقررًا بموجب القانون المصري أو قواعد حماية المستهلك.

## 4. الإفصاح المسؤول عن الثغرات
- قناة استقبال منشورة: security@cyberjocx.com **لا تُعلن قبل إنشاء البريد واختباره**؛ وحتى ذلك الحين لا يُدرج البريد كموجود.
- يطلب من الباحث وصفًا واضحًا للأثر وخطوات إعادة الإنتاج دون الوصول إلى بيانات مستخدمين أو تعطيل الخدمة.
- النطاق المسموح هو الأصول التي يملكها CyberJocx أو صرح بها مالكها كتابةً. لا يشمل الاختبار أي شريك أو مزود خارجي ما لم يوجد تفويض صريح.
- يحظر اختبار DoS أو التصيد أو الهندسة الاجتماعية أو استخراج بيانات شخصية أو نشر الثغرة قبل التنسيق.
- تُحدد مواعيد استلام وإقرار ومتابعة، ومسار لتقييم الخطورة والإصلاح، ومتى وكيف يتم الإقرار بالفضل بموافقة الباحث.
- لا تُعد السياسة دعوة لاختبار هجومي غير محدود، ولا وعدًا بمكافأة إلا في برنامج مكتوب وممول بشروط صريحة.

## 5. AI / NEXUS: الحدود والشفافية
- النسخة التجريبية المقترحة: سقف شهري **25,000 token إجماليًا** للباقة الأساسية و**75,000 token إجماليًا** للباقة الأعلى، شاملاً الإدخال والإخراج. هذه حدود تجريبية يجب اختبارها على النموذج المزود قبل إعلانها؛ لا تُفعل قبل قياس التكلفة الفعلية لكل 1,000 token وتطبيق حدود استخدام صلبة.
- يسجل النظام لكل طلب: نوع النموذج، tokens input/output، تكلفة المزود عند توفرها، العضوية، الخصائص المستخدمة، والأخطاء. يراجع المسؤول المالي/التقني الاستهلاك أسبوعيًا أول شهرين.
- تظل التكلفة المتغيرة العامة 20% في النموذج المالي **اختبار حساسية فقط** وليست تكلفة AI محسومة أو نسبة تكلفة فعلية.
- لا ينبغي أن ترسل المنصة تلقائيًا كلمات مرور أو مفاتيح API أو بيانات عملاء أو أسرار إلى مزود AI. يجب تحذير المستخدمين قبل إدخال محتوى حساس.
- تُوضح حدود دقة AI ومراجعته البشرية، ويُمنع تقديم مخرجاته على أنها استشارة قانونية أو ضمان مهني.
